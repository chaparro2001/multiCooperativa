# 06 · Design system migration

**Date**: 2026-10-22 · **Status**: Draft

Gap analysis between the design system in [design-system/](design-system/README.md) (generated from [05-ui-design-brief.md](05-ui-design-brief.md)) and the current app in `apps/mobile`, and a phased plan to adopt it. The migration is **visual**: same screens, same data, same copy, same permissions. Anything in the design that needs new behaviour or new backend data is listed separately in [§5](#5-items-that-need-a-decision) and is out of scope until decided.

**Context**: the feature freeze was 22/10 and delivery is 26/10. Milestone 7 (security review, coverage report, thesis report, demo video) and Milestone 6 still have open tasks. The plan therefore budgets about **1.5 days** of UI work (23/10 and the morning of 24/10) and leaves 24/10 afternoon for regression and screenshots, so the demo video on 25/10 records the final look. Everything not marked "Before delivery" in [§7](#7-recommended-scope-before-delivery) waits.

## 2. Tokens

Source of truth after the migration: `apps/mobile/src/ui/theme.ts` computes every brand-derived tone from the brand with `mix()`; `tokens.json` documents the result for the 8 presets. `tokens.css` stays preview-only.

### 2.1 Colours: presets against `mix()`

Recomputing every preset with the app's `mix()` (`primary-container` = brand 85 % white, `on-primary-container` = brand 60 % black, `secondary` = brand 50 % `muted`, `elevation-n` = white with 5/8/11/12/14 % brand) gives the same value as `tokens.json` in 55 of the 64 derived values (8 tokens × 8 presets). The 9 differences are one unit in a single channel, so the design tool rounded differently; they are not a design intent:

| Preset | Token               | `mix()` (app) | `tokens.json` |
| ------ | ------------------- | ------------- | ------------- |
| blue   | `secondary`         | `#3f5f88`     | `#3e5e88`     |
| teal   | `secondary`         | `#376d6b`     | `#376c6b`     |
| violet | `secondary`         | `#6646a1`     | `#6646a0`     |
| wine   | `secondary`         | `#7e3d5b`     | `#7e3d5a`     |
| amber  | `secondary`         | `#8a5b39`     | `#8a5b38`     |
| slate  | `secondary`         | `#4b525d`     | `#4b525c`     |
| amber  | `elevation-5`       | `#f5e7dd`     | `#f4e7dd`     |
| red    | `primary-container` | `#f5dddd`     | `#f4dddd`     |
| slate  | `primary-container` | `#e1e3e5`     | `#e1e2e5`     |

**Decision**: keep `mix()` unchanged (it also serves custom `#RRGGBB` colours, which a lookup table cannot) and correct these 9 values in `tokens.json` and `tokens.css`. `PRESET_COLORS` in `features/branding/brand-color.ts` is upper case and `tokens.json` lower case; values are equal.

### 2.3 Typography

Paper's `MD3LightTheme.fonts` already has exactly the token scale (displaySmall 36/44 … labelSmall 11/16, weights 400/500) and the system font. **No theme change.** Usage changes, applied screen by screen in Phase 3:

- Body copy (announcement body, point descriptions, empty states, chat) → `bodyLarge`. Meta lines → `bodyMedium` `muted` (rows use `bodySmall` today). Fine print stays `bodySmall`.
- Row and tile titles → `titleMedium` (home tiles use `titleSmall`; unread announcement rows switch between `titleMedium` and `bodyLarge`, the design keeps `titleMedium` and only changes weight).
- Detail titles `headlineSmall` (already); login/invitation titles `headlineLarge` (invitation uses `headlineSmall`).
- Amounts: `fontVariant: ['tabular-nums']` inside a new `Money` component.

### 2.4 Spacing, radii, shadows, sizes

Add to `theme.ts` (plain constants, not inside the Paper theme so `MD3Theme` stays the stock type):

```ts
export const space = { 1: 4, 2: 8, 3: 12, 4: 16, 5: 20, 6: 24, 8: 32, 10: 40, 12: 48 } as const;
export const radius = { xs: 4, sm: 8, md: 12, bubble: 14, lg: 16, full: 999 } as const;
export const size = {
  control: 48,
  field: 56,
  headerIcon: 44,
  icon: 24,
  iconTile: 40,
  iconEmpty: 48,
  badge: 22,
  countBadge: 20,
  chip: 32,
  composerMax: 120,
} as const;
export const shadow = {
  1: '0 1px 2px #1b1b1b1f, 0 1px 3px 1px #1b1b1b14',
  2: '…',
  3: '…',
} as const; // RN `boxShadow` style
```

`SCREEN_PADDING` (24) and `SCREEN_MAX_WIDTH` (960) in `ui/screen.tsx` become `space[6]` and `layout.maxWidth`. React Native 0.86 (new architecture) and react-native-web accept the `boxShadow` style string, so the CSS values in `tokens.json` can be used as they are; no platform-specific `shadowColor`/`elevation` code.

### 2.5 `theme.test.ts`

The existing tests keep passing (no derivation changes). Add:

1. A table test with the 8 presets: `createPaperTheme(preset)` gives the `primary-container`, `on-primary-container`, `secondary` and `elevation.level1…5` values of the corrected `tokens.json` (values copied into the test, not read from `docs/`, so the app does not depend on the docs folder).
2. `onPrimaryContainer` on `primaryContainer` ≥ 11:1 and `primary` on `background` ≥ 5:1 for every preset (the system's documented claims).
3. `scrim`/`backdrop` value and that the spacing scale is the 4-pt scale (cheap guard against accidental edits).

## 8. ADR and dependencies

- **ADR-024 · Adopt the design system** (recommended, short): `docs/design-system/` is the visual reference for the app; tokens map onto `ui/theme.ts`, and the theme's `mix()` derivation is the authority for brand-derived values (the JSON documents it); the kit in `src/ui` grows with the components in [§3](#3-components); behaviour items in [§5](#5-items-that-need-a-decision) are not adopted by this ADR. It extends ADR-018 and ADR-020 without changing them.
- **Dependencies**: none. Skeleton shimmer uses React Native `Animated` (or the already installed `react-native-reanimated`) and `AccessibilityInfo`; shadows use the `boxShadow` style; icons stay `MaterialCommunityIcons`. A MapCard would need `react-native-maps` plus a geocoding source, which is why it is cut.
- **Plan**: when work starts, add a "Design system migration" entry to [03-implementation-plan.md](03-implementation-plan.md) after the performance section, referencing this document.
